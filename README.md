# workplace-writing

> 职场写作助手 Agent Skill

基于专业职场写作课程方法论（金字塔原理 + SCQA 结构），帮助用户编写或优化各类职场文案：
年终总结、进展汇报、调查报告、请示、邮件、商业计划书、项目计划、工作计划、加薪申请、会议记录、活动方案等。

## 安装

```bash
# 方式一：skills CLI
npx skills add git@github.com:gaorun/workplace-writing.git

# 方式二：直接作为参考资料 cat 进 context
```

## 使用

提出写作需求即可，例如：

- "帮我写一份年终总结"
- "这封邮件怎么回复比较好"
- "写一份加薪申请"
- "帮我把这段报告改得更有说服力"

技能先分模式，两种模式的流程不同：

- **从零写**：识别写作类型（总结/调查报告/申请/计划/邮件）→ 收集信息 → TCS 三步构思 → 按金字塔结构出稿。
  收集信息分两条路：叙事型文案（邮件、请示、会议记录）逐轮提问，单轮最多 3 问、最多 2 轮；数据密集型文案（总结、汇报、申请、方案、计划书）先定位塔尖，再给一张数据清单一次性回填，只对塔尖依赖的缺口追问。
- **改写 / 润色**：不收集信息、不擅自重写全文，输出三节——诊断、修改（原文 → 改后 + 理由）、如果重写会怎么写。

两条底线贯穿两种模式：**不编造**（缺的信息用 `【待补：XX】` 占位）；**不擅自重写**（用户没要新版本就不重写全文）。
数字分三种成色：测得值直接写并标来源；估算值必须有锚点与口径、取保守值、不用精确小数；无锚点的不许出现具体数字，改用可核对的事实或换对比轴。

## 文件结构

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 跨类型的规则与流程：模式判断、类型路由、提问与停止规则、TCS、金字塔与 SCQA、语言质感与温度、输出契约 |
| `types.md` | 每种文案的类型卡片：本质与基调、提问清单、数据框架、金字塔结构、写作要点、成品示例（年终总结、加薪申请、邮件三篇带完整示例） |

维护约定：同一件事只写一处——跨类型的规则改 `SKILL.md`，只对某一种文案成立的改 `types.md`。
